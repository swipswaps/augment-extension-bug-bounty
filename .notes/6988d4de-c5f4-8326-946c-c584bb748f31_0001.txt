Answers to your questions
1. "Is this a VS Code issue or an Augment issue?"
Both, but primarily Augment.

VS Code's fault: Shell Integration output capture has a race condition (500ms data stream timeout, VS Code issue #253265). This is why the m6 (VSCodeEvents) strategy fails.
Augment's fault: T0 (ScriptCaptureStrategy) was built to work around VS Code's limitation, but it has its own bugs:
ensureTerminalSessionActive() failures are logged at debug level (invisible), so there's no way to diagnose what's happening
When T0's session fails, the fallback chain leads to the same broken Shell Integration path it was designed to avoid
The getOutputAndReturnCode() has a timing race: if it reads the script file before the command finishes writing, it returns "file has not grown" and falls through to the broken path
The final fallback is clipboard — which is empty because no one put anything there
2. "Why did changing the setting to 'Augment' not fix it?"
Because the setting only switches the strategy class from m6 to T0. But T0 requires:

A script session initialized for each terminal (setupTerminal() / ensureTerminalSessionActive())
The session to stay alive (the script process must be running in the terminal's PTY)
Proper timing between file writes and reads
The first command after the switch (12:44:58) hit a terminal with no session data. After that, we can't see what happened because all messages are at debug level. The script file at /tmp/augment-script-*.log IS being written to (we confirmed 6,613 bytes of terminal capture), but hybridReadOutput() may be reading it before the command output is fully written.

3. "Is there a hidden rule or command?"
Yes — the log level. The Augment extension's debug log entries contain all the evidence for whether T0 is working or failing, but they're filtered out of the visible log. If there were a way to set the Augment extension log level to debug, every failure path would be visible.

There is also a VS Code setting that may help:

"augment.experimental.terminal.vscodeTerminalStrategy": "Augment"
This is already set. But it needs a full VS Code restart (not just a config change) to ensure:

All old terminals are destroyed
New terminals get T0 session initialization from the start
No stale _terminalSessions Map entries
4. "Augment is unusable without reliable terminal writing and reading"
Correct. The evidence shows the output capture chain has three layers of fallback, and on this system all three fail:

Layer	Method	Why it fails

3	Clipboard	Nothing writes to clipboard
