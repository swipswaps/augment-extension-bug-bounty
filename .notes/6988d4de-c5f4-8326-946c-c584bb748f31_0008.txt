Summary

When a terminal closes, the handler calls:

cleanupTerminal(h)

before reading the captured output.

cleanupTerminal() deletes:

/tmp/augment-script-*.log

This guarantees that subsequent output retrieval returns an empty string.

This is not a timing issue — it is a hardcoded execution order.

~/.vscode/extensions/augment.vscode-augment-0.754.3/out/extension.js

What cleanupTerminal() Does

Inside the completion strategy:

Retrieves session from _terminalSessions

Kills script process

Deletes script capture file

fs.unlinkSync(r.scriptFile)

This removes the only authoritative output source.

Deterministic Failure Chain

Terminal closes

onDidCloseTerminal fires

cleanupTerminal(h) runs

Script file is deleted

Session removed from Map

hybridReadOutput() executes

Script capture unavailable

Shell integration stream often undefined

Clipboard fallback empty

Resolver returns:

output: ""
Verified Fix
Change

Move:

cleanupTerminal(h)

to after the output-reading loop.

Patched Execution Order
onDidCloseTerminal(async h=>{
  this._logger.debug(...),
  this._removeLongRunningTerminal(h);

  for (...) {
     hybridReadOutput(...)
  }

  e._completionStrategy?.cleanupTerminal(h)
})
Why This Fix Works

Before:

Output source deleted first

Read attempt always fails

After:

Output is read while:

Script file still exists

Session still in _terminalSessions

Cleanup occurs only after resolver completes.

Explanation of the Fix (Annotated, Step-by-Step)
What actually changed in logic

Only one thing:

The cleanup call moved from:

BEFORE reading output


to

AFTER reading output

Why that single change is enough

Because the script capture architecture depends on three live resources:

Session entry in _terminalSessions

Running or recently finished script process

Log file on disk

The original order destroyed all three before reading.

The new order preserves them long enough for:

hybridReadOutput()


to succeed.

Why the size changed by −1 byte

Minified bundle:

Original had ,cleanupTerminal(...)

After move, leading comma removed

No functional risk — just syntactic compression artifact.

Why restart is mandatory

VS Code extension host:

Loads compiled JS bundle once

Keeps it in memory

Does not re-eval the file on disk

So without restart:

Old buggy handler still executes

Why this fix is safe

It does not change:

Capture strategy selection

Session creation

PTY handling

Shell integration

Process lifecycle

It only changes when cleanup occurs.

What failure mode still exists (but is separate)

If the terminal is disposed before the command finishes:

The script log may be incomplete

Output may still be partial

That is a different race (process completion vs terminal disposal), not the deletion bug.
