/***************************************************************************************************
SECTION 3 — CONTROLLED EXPERIMENT PLAN

We execute experiments in isolation.

----------------------------------------------------------------------------------------------------
EXPERIMENT 1 — Baseline Idle
----------------------------------------------------------------------------------------------------
Goal:
    Establish FD + TCP steady state with NO streaming calls.

Procedure:
    Disable getRemoteAgentOverviewsStream invocation.
    Observe 10 minutes.

Expected:
    FD stable.
    TCP stable.

If NOT stable:
    Stream is NOT primary cause.
    Investigate other lifecycle leaks first.

----------------------------------------------------------------------------------------------------
EXPERIMENT 2 — Single Stream, No Timeout
----------------------------------------------------------------------------------------------------
Goal:
    Confirm proper cleanup on normal completion.

Procedure:
    Allow ONE stream to complete successfully.
    No artificial timeout.
    No retries.

Expected:
    FD returns to baseline.
    TCP returns to baseline.
    Undici stats show 0 pending.
    No CLOSE_WAIT accumulation.

Failure here = fundamental cleanup bug.

----------------------------------------------------------------------------------------------------
EXPERIMENT 3 — Forced Timeout, No Retry
----------------------------------------------------------------------------------------------------
Goal:
    Confirm abort path cleanup.

Procedure:
    Trigger timeout once.
    DO NOT allow retry.
    Log:

        abortController.abort()
        response.body.cancel()
        iterator.return()

Expected:
    FD returns to baseline.
    TCP ESTABLISHED does NOT grow.
    No CLOSE_WAIT accumulation.

If FD grows here:
    Timeout path leak confirmed.

----------------------------------------------------------------------------------------------------
EXPERIMENT 4 — Retry Enabled
----------------------------------------------------------------------------------------------------
Goal:
    Detect latch re-entry condition.

Procedure:
    Allow timeout + automatic retry loop.
    Observe 5–10 cycles.

Expected:
    Only ONE active stream at any time.
    No monotonic TCP growth.
    No exponential FD growth.

If TCP grows linearly with retries:
    Stream retry storm confirmed.

If renderer forks increase:
    Webview reload loop confirmed.

----------------------------------------------------------------------------------------------------
EXPERIMENT 5 — Webview Disabled
----------------------------------------------------------------------------------------------------
Goal:
    Confirm whether renderer churn drives leak.

Procedure:
    Disable webview initialization entirely.
    Run streaming.

If leak disappears:
    Webview reload cycle is primary driver.

***************************************************************************************************/



/***************************************************************************************************
SECTION 4 — STREAM LIFECYCLE COMPLIANCE REQUIREMENTS

A streaming request MUST obey:

    let response;
    try {
        response = await fetch(...);
        for await (const chunk of response.body) {
            // consume
        }
    } finally {
        if (response?.body) {
            await response.body.cancel();
        }
    }

AND on timeout:

    abortController.abort();

AND retry MUST NOT execute unless:

    previousStreamState === "fully_cleaned"

Mandatory invariant:

    activeStreamCount <= 1

If violated → latch re-entry condition exists.

***************************************************************************************************/



/***************************************************************************************************
SECTION 5 — PERMANENT FIX REQUIREMENTS

To eliminate latch re-entry permanently:

1) Introduce global single-flight guard:

        if (streamInFlight) return;
        streamInFlight = true;

2) Enforce structured cleanup:

        try { ... }
        finally {
            streamInFlight = false;
        }

3) Disallow recursive retry:
        Replace immediate retry with backoff scheduler.

4) Prevent webview reload until:
        streamInFlight === false

5) Ensure abort path explicitly:
        - abortController.abort()
        - response.body.cancel()
        - iterator.return()

6) Add hard assertion:

        if (activeStreams > 1) {
            throw new Error("STREAM RE-ENTRY DETECTED");
        }

If these are not implemented together,
re-entry can still occur.

***************************************************************************************************/

/***************************************************************************************************
SECTION 7 — RAW SOCKET VS POOL CONFIRMATION

Interpretation logic:

IF:
    TCP ESTABLISHED grows with FD growth
THEN:
    Raw socket leak or pooled socket not returned.

IF:
    Undici stats show growing "busy" or "pending"
THEN:
    Pool leak.

IF:
    TCP mostly TIME_WAIT
THEN:
    Retry storm.

IF:
    TCP small but FD huge
THEN:
    IPC or pipe leak (webview churn).

Conclusion must match metrics.
