how do I detect all hidden terminals in fedora 43 terminal?

Good question — on Fedora 43 there isn’t really a concept of a “hidden” terminal in the spooky sense 😄, but there are several common ways terminal sessions can exist without being obvious. Below is a complete, audit-style checklist that will surface all of them.

1️⃣ List every terminal process running (ground truth)

This catches everything, regardless of desktop, workspace, or visibility.

ps -eo pid,ppid,tty,stat,cmd | grep -E 'bash|zsh|fish|sh|tmux|screen|pty' | grep -v grep


Key things to watch:

tty = pts/* → attached to a pseudo-terminal

tty = ? → background, detached, or service-spawned shell

stat includes T → stopped (often “hidden” via Ctrl-Z)

stat includes S or R → active

If it has a shell (bash, zsh) and a TTY, it’s a terminal session.

2️⃣ Show active TTYs and logins
who


and

w


If a shell is alive but not listed here, it’s detached, backgrounded, or inside a multiplexer.

3️⃣ Detect terminals hidden via job control (Ctrl-Z, &)

In each terminal you have open:

jobs -l


Then system-wide:

ps -eo pid,tty,stat,cmd | grep ' T '


That T means stopped but still alive — extremely common “where did that terminal go?” case.

4️⃣ Find tmux sessions (very common culprit)
tmux ls


If this returns sessions, you have terminals running that are completely invisible until attached:

tmux attach


Also detect tmux-spawned shells:

ps -eo pid,ppid,tty,cmd | grep tmux | grep -v grep

5️⃣ Find screen sessions
screen -ls


Detached screens are effectively hidden terminals.

6️⃣ List terminals per desktop / workspace (GNOME)

Fedora 43 uses GNOME by default.

List GNOME Terminal / Ptyxis processes:
pgrep -a gnome-terminal
pgrep -a ptyxis


To see which workspace they’re on:

wmctrl -lp


If a terminal is on another workspace, it’ll appear here even if you forgot it existed.

7️⃣ Identify terminals with no visible window

This is the “stealth” case.

ps -eo pid,tty,cmd | awk '$2 ~ /^pts\// {print}'


Then cross-check windows:

wmctrl -lp | awk '{print $3}'


If a PID has a pts/* but no window, it’s:

Detached (tmux, screen)

Backgrounded

Spawned by a service or script

8️⃣ See who spawned them (parent process audit)
ps -eo pid,ppid,cmd | grep bash


Then:

ppid = 1 → orphaned / daemon-spawned shell

ppid = tmux → multiplexer

ppid = systemd → service or user unit

9️⃣ Nuclear option: show every pseudo-terminal
ls -l /dev/pts


Each numbered entry corresponds to an active terminal device.

Map it back:

ps -eo pid,tty,cmd | grep pts/3

🔍 Summary: What people usually mean by “hidden terminals”
Cause	Detection
Stopped shell (Ctrl-Z)	ps ... stat=T, jobs -l
Detached tmux	tmux ls
Detached screen	screen -ls
Other workspace	wmctrl -lp
Background shell	ps -eo tty=?
Service-spawned	ppid=systemd
Forgotten pts	/dev/pts/*

ps -eo pid,ppid,tty,stat,cmd --sort=tty \
| awk '
BEGIN {
  printf "%-8s %-8s %-7s %-6s %-12s %s\n", "PID", "PPID", "TTY", "STAT", "CLASSIFICATION", "COMMAND"
}
{
  classification="unknown"

  # Only care about shells
  if ($5 ~ /(bash|zsh|fish|sh)$/ || $6 ~ /(bash|zsh|fish|sh)/) {

    if ($3 ~ /^pts\//) classification="visible-terminal"

    if ($4 ~ /T/) classification="STOPPED-HIDDEN"

    if ($0 ~ /shellIntegration-bash\.sh/) classification="VSCODE-terminal"

    if ($2 == 1 && $3 == "?") classification="ORPHANED-DANGER"

    printf "%-8s %-8s %-7s %-6s %-12s %s\n", $1, $2, $3, $4, classification, substr($0, index($0,$5))
  }
}'

🔍 How to read the output (important)
Classification	Meaning

VSCODE-terminal	Spawned by VS Code
STOPPED-HIDDEN	Suspended via Ctrl-Z or task interruption
ORPHANED-DANGER	Detached shell with no parent (rare, investigate)

If a shell matches multiple conditions, the most serious label wins (STOPPED > VSCODE > visible).
